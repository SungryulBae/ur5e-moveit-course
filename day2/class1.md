# 1교시: 카메라 제어 및 데이터 수집

## 오늘 할 것
- RGB 카메라가 3D 세상을 2D 이미지로 담는 원리(핀홀 카메라 모델)를 이해한다
- 로봇을 움직이며 카메라 이미지와 로봇 상태를 함께 수집한다
- 로봇 학습에서 자주 쓰는 전처리 · 증강을 해 보고 시각화한다

## 미리 알아 둘 것
### RGB 카메라
- 렌즈를 지난 빛이 이미지 센서의 수많은 픽셀에 닿고, 각 픽셀은 빨강(R) · 초록(G) · 파랑(B) 세기를 0~255 숫자로 기록한다
- 이미지 = 높이 × 너비 × 3 크기의 숫자 배열 (예: 240 × 320 × 3)

### 핀홀 카메라 모델
3D 점 (X, Y, Z) (카메라 기준) → 픽셀 (u, v)
```
u = fx · X / Z + cx        fx, fy : 초점 거리 (픽셀 단위)
v = fy · Y / Z + cy        cx, cy : 이미지 중심
```
- 이 4개 숫자를 모은 3×3 행렬을 **내부 파라미터 K**라고 한다
- 멀리 있는 물체(Z가 큼)일수록 작게 보이는 이유가 이 식의 `/ Z`
- MuJoCo 카메라는 화각(fovy)만 주면 K가 정해진다: `fy = (이미지 높이 / 2) / tan(fovy / 2)`

### 오늘 쓰는 로봇 장면
- MuJoCo 속 **UR5e + Robotiq 2F-85 그리퍼**, 바닥 위의 빨간 큐브(4 cm), 카메라 2대
  - `front`: 작업대를 비스듬히 내려다보는 고정 카메라
  - `wrist`: 그리퍼 뒤에 달려 손가락 사이를 보는 카메라 (로봇과 함께 움직임)
- 로봇은 **미리 짜 둔 규칙(스크립트)**이 움직입니다. 오늘은 카메라와 데이터에 집중하고, 로봇 환경의 내부(상태 · 행동 · 보상)는 5교시에 직접 살펴봅니다

## 실습 1. 로봇을 움직이며 데이터 수집
```bash
cd ~/day2_work
$MUJOCO_PYTHON -m day2_rl.c1_camera_collect --view   # MuJoCo 창으로 로봇을 보면서 수집
```
- 창은 수집이 끝나면 자동으로 닫힙니다. 마우스로 시점을 돌려 보세요 (왼쪽 드래그: 회전, 오른쪽 드래그: 이동, 휠: 확대)
- 창 없이 빠르게: `--view` 빼고 실행 (저장되는 데이터는 같음)
- 규칙 기반 전문가가 큐브를 집어 드는 동안(가끔 무작위로 흔들며) 60 프레임을 모은다
- 저장: `camera_data.npz` — 정면 · 손목 이미지, 관절 각도, 끝단 위치, 큐브 위치, 정면 카메라의 K
- 같은 순간의 **이미지와 로봇 상태를 짝지어** 저장하는 것이 핵심 (로봇 학습 데이터의 기본 형태)

## 실습 2. 전처리와 시각화
```bash
$MUJOCO_PYTHON -m day2_rl.c1_preprocess
```
생성되는 그림을 열어 보세요 (`xdg-open c1_samples.png` 또는 파일 탐색기)

| 그림 | 볼 것 |
|---|---|
| `c1_samples.png` | 같은 순간의 정면 · 손목 카메라 이미지. 손목 카메라는 손가락 사이로 큐브를 크게 본다 |
| `c1_preprocess.png` | 원본 → 가운데 자르기 → 84×84로 줄이기 → 흑백 → 정규화 → 밝기 증강 → 무작위 이동 증강 |
| `c1_projection.png` | 큐브의 3D 위치를 핀홀 모델 식으로 계산한 픽셀(하늘색 +)이 실제 이미지의 큐브 위에 찍히는지 |
| `c1_trajectory.png` | 수집하는 동안 끝단 · 큐브 위치 변화 (큐브가 들어 올려지는 순간을 찾아보기) |

### 왜 이런 전처리를 할까
| 기법 | 이유 |
|---|---|
| 자르기 · 줄이기 | 계산량을 줄인다 (240×320×3 = 23만 개 → 84×84×3 = 2만 개) |
| 정규화 (평균 0, 표준편차 1) | 신경망이 학습하기 좋은 숫자 범위로 |
| 밝기 증강 | 조명이 바뀌어도 같은 물체로 인식하도록 |
| 무작위 이동 증강 | 카메라가 조금 흔들려도 괜찮도록. 이미지 기반 강화학습에서 효과가 큰 방법 |
